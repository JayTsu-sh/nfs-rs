# NFSv4.2 pre-merge review — 2026-11-02

Review scope: tracked changes and new v4.2 implementation, tests and documents
against main at `b1009a6415e9d96ae2f1dbbbf0f6fe05ef0e5b11`. Machine-local
CodeGraph/Codex configuration and AGENTS.md were excluded from the change.
Two independent code-review axes inspected the implementation and rechecked
the fixes. Both axes passed with no remaining actionable findings.

## Standards

Two initial findings, both resolved:

- P1: v4.2 mutation uncertainty could disappear if cancellation discarded an
  already queued result; a task panic could release barriers without recording
  uncertainty. The shared result slot, explicit acknowledgement and existing
  WRITE ownership guards now preserve uncertainty before barrier release.
  Two deterministic regressions failed against the original code and pass
  after the correction.
- P2: NFSVersion::NFSv4p2 rustdoc incorrectly said optional operations were
  not exposed. It now documents server-dependent optional support.

No additional actionable code-smell findings were reported. Standards sources
were AGENTS.md, CONTRIBUTING.md and CONTEXT.md, with protocol correctness,
data integrity, cancellation and state cleanup prioritized.

## Spec

Three initial findings, all resolved:

- P1: abandoned Python operations lost recovery events when uncertain COPY
  and temporary CLOSE failures were aggregated. Recovery recording now walks
  nested FileClose failures; explicit acknowledgement also retains queued,
  unread owned-operation results. The combined cancellation/aggregation
  regression failed before the correction and passes afterward.
- P2: COPY/CLONE recovery paths identified the source. Both adapters now retain
  the destination, with a targeted path-selection regression.
- P2: the same outdated version rustdoc noted by Standards was corrected.

All requested operations and Rust/Python surfaces were present. Cross-server
asynchronous offload remains outside the selected scope. Unsupported AFX
operations and its partial-deallocation error remain explicit.
