修改后为同一 checkout 的工作树。两边均为 nfs-rs 0.11.1、Rust 1.95.0 release，

本次实现了已批准的两项工作：`BufferedFile::read_at` 复用单段响应，以及

会话槽位或重放保护。减少的是实际的累计输出分配；RSS 并非所有负载都下降。

## 物理环境与方法

设备为 FAS2750 / ONTAP 9.19.1；A/B 对应用户指定的源/目标 LIF，属于同一
SVM。每个入口和协议独立统计，不能共享 baseline。使用既有的
`/deep_sync_nfs` 导出、默认保留源端口、UID/GID 0；未修改服务端配置。
执行器为 Linux 6.8、glibc 2.39、24 个可用 CPU，未设置 malloc 或 Tokio 调优
环境变量。完整 read-back 与 EOF 校验均计入 READ 耗时。

1. 64 MiB 矩阵：两个 LIF × 三协议 × 三次独立重复。每组分别启动 seed WRITE、
   QD1/QD8 READ-only、QD1/QD8 完整写读，以及八个同步起跑的 READ-only 进程。
   单进程读取三轮，并发读每个 worker 读一轮。每版 234 个进程，两版共 468 个。
2. 原始 1 GiB 负载：两个 LIF、三协议分别做 QD8 一次写加一次完整读；v4.1
   另外执行八进程同文件 1 GiB 读取。这些规模扩展各只有一组样本。
3. v4.1 稳态：每个 LIF、每个版本在新进程中以 QD8 连读 256 MiB 文件 32 轮，
   每进程累计读取 8 GiB。它验证连续轮次的稳定性，不代表数小时或全天压力。

本轮比较的是 0.11.1 修改前后，未恢复 0.6.1 的旧预读/回写实现，不能把
八进程的绝对 RSS 与历史报告中的 69 MiB 直接比较。

扩展测试共 52 个进程，两类有效对照合计 520 个进程，半数为修改前基线。
所有内容、EOF、大块释放及适用的稳态检查通过。另有 4 MiB 功能试跑，未混入
下表。所有 run 均持有 tests/performance 两把共享锁、使用唯一 `release-*`

准备/清理由显式指向 FAS fixture 的通用 NFSv4.2 目录辅助器执行。

## 连续 32 轮读取

每格一个新进程；累计分配为全部 32 次 READ 的和。尾段范围是最后三次 idle
采样的 `>=512 KiB` 存活分配量的最大值减最小值，单位 bytes。

| LIF | 版本 | 峰值 RSS MiB | READ 累计分配 GiB | 存活大块尾段范围 | READ 总耗时 s |
| --- | --- | --- | --- | --- | --- |
| A | before | 76.55 | 32.49 | 0 | 76.1 |
| A | after | 76.58 | 24.49 | 0 | 76.1 |
| B | before | 23.50 | 16.22 | 0 | 76.2 |
| B | after | 26.05 | 8.22 | 0 | 75.2 |

四个进程的尾段范围均为 0；CLOSE、UMOUNT 并释放 mount/pattern 后，所有新
增的 Rust 大块分配均释放。基线本来也没有显示持续的 reply 留存，因此本次
修复针对额外复制和分配压力，不能描述为修复了一个已证实的 slot 内存泄漏。

另外逐一复核了全部 520 份原始报告的整体存活堆尾段，最大范围为 5128 bytes，
所有适用案例均在默认 1 MiB 的诊断噪声预算内。这项检查覆盖小于 512 KiB 的
分配，避免只观察大块而漏掉小块增长；单轮案例仍未记为稳态通过。

## 适用范围

- 稳定收益是单段返回值不再复制、累计分配减少；RSS 仍受分配器、线程调度、
  实际协议路径与响应 backing 大小影响。返回的 `Bytes` 可以持有整个响应
  backing，它不保证分配容量恰好等于 payload 长度。
- 诊断工具对 Rust `System` 分配请求计数，未覆盖 libc 内部分配、线程栈等；
  realloc 的内部临时峰值不在请求计数中。VmRSS/VmHWM 是近似计数。
- 本轮未做物理故障/取消恢复、数小时压力或独立 DS 抓包证明；没有将这些情形
  记为通过。默认忽略的 Rust lab suite 和跳过的 Python physical case 也没有
  被这里的基准替代。
- 现有跨环境发布性能 manifest、accepted baseline 和阈值均未改动。实际导出
  与其中 FAS `/nfsrs_v40_test` 的 accepted fixture 不同，不能套用其阈值；
  本轮未运行全环境发布性能 gate，也未执行发布。
