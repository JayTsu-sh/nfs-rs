# NFS 服务连通性与协议恢复

设计、开发、测试和 review 按实际协议考虑 NFS／MOUNT／portmapper、元数据与 pNFS 数据服务及协议回调链路的连接建立失败、运行中断连、静默丢包和请求超时。产品扫描防抖、迁移代次、源端删除、ClickHouse 和产品 callback 由上层负责。

- **准确证据**：保留原始结构化原因、操作阶段、发送及执行证据。区分连接故障与认证／权限、服务端状态和协议错误；后续重连或绑定失败不能掩盖最初明确断连的原因，Rust／Python 边界须保留可识别分类。
- **有界恢复**：明确连接、排队、发送、等待、重连／绑定及整体恢复的时限和次数，同一次恢复共享截止时间，采用协议安全的短时恢复并及时上报。调用方的扫描约 3 秒窗口不在本库硬编码，也不机械应用到普通操作；静默丢包检测与恢复耗时分别约束和报告。
- **安全重放**：按协议版本和操作证明是否可重放，区分未发送、部分发送、已发送未知结果及已确认完成；响应丢失不能被当作未执行，修改操作保留不确定结果。
- **状态与资源**：TCP 恢复后核验句柄、OPEN、锁、session／sequence、lease 和 layout 等相关状态；元数据服务恢复不代表数据服务或旧状态有效。取消与部分帧失败时收束请求，隔离不可复用传输，按所有权处理资源和后台完成。

## 真实故障注入

新增或修改连接、超时、重试、取消及恢复逻辑，必须在受影响的真实协议链路实施受控故障注入，按场景覆盖闪断、持续断连、静默丢包／超时、重连绑定失败和恢复。确定性测试不能替代真实链路验收。

验证错误分类、检测与恢复时限、安全重放、故障期间取消、最终数据及句柄／状态／后台任务收尾，按影响范围验证 Rust／Python 接口和正常性能／内存开销。报告注入对象与方式、实际结果、未覆盖环境及能力限制，遵守实验室允许范围和无条件清理要求。

本页是设计与验收要求，不代表所有协议或设备已完成对应实现或实测。
