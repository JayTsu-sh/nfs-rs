# NFSv4.0 reuse boundary in the current NFSv4.1 client

Research baseline: `nfs-rs` commit `203d10373e328c6e98a8a616f5f97c8ca59432e1`, RFC 7530 (NFSv4.0), and RFC 8881 (NFSv4.1).

## Answer

The safe boundary is **below the protocol engine and above it, but not through it**. Reuse the generic TCP/RPC machinery, AUTH_SYS, bounded XDR primitives, common NFSv4 wire codecs after separating them from minor-version policy, public data types, and version-neutral `Mount` helpers. Build a distinct NFSv4.0 engine that owns client identity, request replay, owner sequencing, lease/recovery, callbacks, and teardown. Do not parameterize `Mount41` with `minorversion = 0`: its request path, recovery path, callback path, state lifetime, and pNFS behavior all assume sessions.

## Compatibility matrix

| Area | Reuse decision | Reason / required seam |
|---|---|---|
| TCP connection and reserved-port selection | Reuse unchanged | NFSv4.0 and v4.1 both use NFS program `100003`, RPC version 4, normally TCP/2049. The project already keeps connection establishment outside `nfs41` ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/lib.rs#L70-L133)). |
| RPC record marking, XID demultiplexing, AUTH_SYS, timeouts | Reuse primitives, not retry policy unchanged | `RpcClient` already multiplexes requests and frames record-marked TCP RPC ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/rpc/mod.rs#L226-L284)). Its retry loop issues a fresh XID and automatically retransmits after timeout/reconnect ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/rpc/mod.rs#L744-L867)); NFSv4.0 replay-sensitive owner requests must instead preserve the logical request and seqid until the outcome is known. The v4.0 engine must control whether a call may be retried. |
| Generated `nfsstat4` and common scalar/XDR types | Reuse after extracting a common v4 module | RFC 7530 defines the common NFSv4.0 types and status values; RFC 8881 extends them. A v4.1-superset status decoder is wire-safe for common responses, but exposing it from `nfs41` leaks ownership and makes minor-version legality unclear ([RFC 7530 XDR](https://www.rfc-editor.org/rfc/rfc7530.html#section-16), [current generated input](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/xdr/nfs4.x)). Generate or hand-maintain a common v4.0 schema plus explicit v4.1 extensions; do not send extension operations under minor version 0. |
| COMPOUND envelope and common operation codecs | Extract and reuse codecs; do not reuse `CompoundBuilder` as-is | The envelope differs only by the `minorversion` field, and operation numbers 3–39 are the v4.0 set ([RFC 7530 §16.2–16.41](https://www.rfc-editor.org/rfc/rfc7530.html#section-16.2)). The current builder hard-codes minor version 1 ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/compound.rs#L963-L983)), assumes the first result is `SEQUENCE`, and applies the session reply-cache policy ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/compound.rs#L277-L323)). Create a minor-version-neutral codec plus separate `Compound40Builder`/`Compound41Builder` policy layers. |
| Common operations | Reuse encoders/decoders after conformance tests | ACCESS, CLOSE, COMMIT, CREATE, DELEGRETURN, GETATTR, GETFH, LINK, LOCK/LOCKT/LOCKU, LOOKUP/LOOKUPP, OPEN/OPENATTR, PUTFH/PUTROOTFH, READ/READDIR/READLINK, REMOVE/RENAME, RESTOREFH/SAVEFH, SETATTR, and WRITE use the v4.0 operation numbers already represented by the current builder ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/compound.rs#L32-L75)). Result skipping for those common operations is structurally reusable ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/compound.rs#L1187-L1410)). |
| NFSv4.0-only operations | New codecs and engine behavior | The current operation enum omits DELEGPURGE (7), RENEW (30), SETCLIENTID (35), SETCLIENTID_CONFIRM (36), and RELEASE_LOCKOWNER (39), all required parts of the v4.0 operation set ([RFC 7530 §16](https://www.rfc-editor.org/rfc/rfc7530.html#section-16)). These are not aliases for v4.1 session operations. |
| NFSv4.1-only operations and pNFS | Never expose to v4.0 | BIND_CONN_TO_SESSION, EXCHANGE_ID, CREATE_SESSION, DESTROY_SESSION, pNFS layout/device operations, SEQUENCE, TEST_STATEID, FREE_STATEID, DESTROY_CLIENTID, and RECLAIM_COMPLETE have op numbers above the v4.0 range and are minor-version-1 facilities ([RFC 8881 §18](https://www.rfc-editor.org/rfc/rfc8881.html#section-18)). `layout`, `pnfs_io`, DS sessions, channel-limit diagnostics, and layout callback counters remain v4.1-only. |
| Attributes, ACL, owner/group, and common attribute models | Reuse common codecs after correcting documentation and making the bitmap version-aware | Contrary to the comment in `attrs.rs`, RFC 7530 already assigns `filehandle=19`, `fileid=20`, `mode=33`, `owner=36`, and `mounted_on_fileid=55`; v4.1 did **not** insert FILEHANDLE ([RFC 7530 §5.8](https://www.rfc-editor.org/rfc/rfc7530.html#section-5.8), [misleading comment](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/attrs.rs#L1-L31)). The current standard bitmap and core decoder are therefore largely common. ACL attribute 12 and ACE wire format are explicitly v4.0 ([RFC 7530 §6](https://www.rfc-editor.org/rfc/rfc7530.html#section-6), [current codec](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/acl.rs#L1-L119)). Keep v4.1-only attributes behind a version-specific registry and validate server-returned bitmaps. |
| OPEN arguments and delegation preference | Share base fields only; version-specific encoder required | The current `OpenArgs` always ORs `OPEN4_SHARE_ACCESS_WANT_NO_DELEG` or `WANT_WRITE_DELEG` into `share_access` ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/compound.rs#L1011-L1044)). Those WANT bits are v4.1 extensions; RFC 7530 v4.0 defines only READ/WRITE/BOTH share access ([RFC 7530 §16.16](https://www.rfc-editor.org/rfc/rfc7530.html#section-16.16)). v4.0 requests must omit them and express callback/delegation capability through SETCLIENTID and callback availability. Common OPEN result/delegation decoding can be reused. |
| Client identity and establishment | Distinct v4.0 engine | v4.1 currently establishes `EXCHANGE_ID → CREATE_SESSION → RECLAIM_COMPLETE` and negotiates fore/back channels ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/session.rs#L1-L85)). V4.0 instead establishes and confirms a `clientid4` with SETCLIENTID/SETCLIENTID_CONFIRM, including callback program/address/identifier, and uses the verifier rules defined by RFC 7530 ([RFC 7530 §9.1.1](https://www.rfc-editor.org/rfc/rfc7530.html#section-9.1.1), [§16.35](https://www.rfc-editor.org/rfc/rfc7530.html#section-16.35)). No `Session`, slot table, channel negotiation, session generation, or binding belongs in the v4.0 engine. |
| OPEN/LOCK state model | Reuse `StateId` and `AccessMode` value types; replace manager semantics | `StateId` and access coverage are common protocol concepts ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/state.rs#L16-L85)). The current manager keys only by filehandle and refcounts one cached open state ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/state.rs#L87-L178)); current OPEN and CLOSE use seqid `0` and static owner strings ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/write.rs#L68-L130), [source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/write.rs#L154-L174)). V4.0 needs explicit open-owner and lock-owner records, per-owner seqid serialization, last-request replay material, confirmed/unconfirmed state, reclaim metadata, and stateid evolution. RFC 7530 makes owner seqids the ordering and replay mechanism ([RFC 7530 §9.1.7](https://www.rfc-editor.org/rfc/rfc7530.html#section-9.1.7)). |
| Request concurrency and replay | Distinct v4.0 scheduler | V4.1 bounds independent concurrent requests with negotiated slots and provides exactly-once behavior through SEQUENCE ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/session.rs#L1-L6)). V4.0 has no slot table. It may multiplex stateless/read-only COMPOUNDs, but each open owner and lock owner needs a serialized lane; ambiguous modifying calls must retain/replay the same logical request according to owner-seqid rules rather than rely on generic fresh-XID retries. |
| Lease renewal and recovery | Distinct v4.0 engine | The current renewer sends `COMPOUND(SEQUENCE)` because any successful v4.1 SEQUENCE renews the lease ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/lease.rs#L1-L6)). V4.0 requires RENEW or another lease-renewing state operation, recovery of clientid/open/lock/delegation state during grace, and RELEASE_LOCKOWNER cleanup ([RFC 7530 §9.6](https://www.rfc-editor.org/rfc/rfc7530.html#section-9.6)). Session re-establishment and `RECLAIM_COMPLETE` must not be reused. |
| Callback transport and callback COMPOUND | New v4.0 listener/dispatcher; reuse low-level RPC/XDR helpers only | The current callback implementation is a v4.1 backchannel on the fore-channel connection, requires CB_SEQUENCE as the first callback operation, and maintains callback slots/replay ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/callback.rs#L1-L31), [source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/callback.rs#L185-L323)). V4.0 callbacks arrive at the separate callback program/netid/address registered by SETCLIENTID; CB_COMPOUND minorversion is 0 and identifies the client with `callback_ident`, without CB_SEQUENCE ([RFC 7530 §10](https://www.rfc-editor.org/rfc/rfc7530.html#section-10), [§16.1](https://www.rfc-editor.org/rfc/rfc7530.html#section-16.1)). Reuse ACE/stateid/filehandle decoders and recall notifications, not the listener topology or parser state machine. |
| Operation modules (`read`, `write`, directory, ACL, xattr) | Reuse algorithms only after routing through a version engine interface | Their COMPOUND shapes mostly use common operations, but response indexes assume a prepended SEQUENCE (for example WRITE reads PUTFH at index 1 and WRITE at index 2) and `write` invokes pNFS before MDS fallback ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/nfs41/write.rs#L15-L59)). Extract version-neutral recipes or helpers that receive an engine and return typed results; do not subclass or flag-switch `Mount41`. Named attributes use v4.0 OPENATTR and common file operations, but their OPEN owner/seqid handling must use the v4.0 state engine ([RFC 7530 §5.3](https://www.rfc-editor.org/rfc/rfc7530.html#section-5.3)). |
| Public `Mount` interface, data types, and path wrappers | Reuse | `Mount` is already version-agnostic and supplies many path wrappers/defaults ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/mount.rs#L61-L115)). Reuse `Attr`, `ObjRes`, `FSInfo`, `FSStat`, ACL/ACE types, streams, `Outcome`, and path splitting. Add a `Mount40Wrapper`; return `None`/`Unsupported` for v4.1-only channel, pNFS, and layout diagnostics. |
| URL/version dispatch | Extend, with the agreed exact-version rule | The current parser maps `"4"` to `NFSv4` and dispatches it to the unsupported branch ([source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/mount.rs#L1303-L1321), [source](https://github.com/JayTsu-sh/nfs-rs/blob/203d10373e328c6e98a8a616f5f97c8ca59432e1/src/lib.rs#L536-L549)). The planned contract requires `version=4.0` and rejects `version=4`; represent v4.0 explicitly and preserve ordered fallback only when the user supplies an explicit list. |

## Recommended module boundary

```text
public Mount + shared data/path helpers
                |
        typed common NFSv4 operations
                |
    +-----------+------------+
    |                        |
v4.0 engine               v4.1 engine
SETCLIENTID               EXCHANGE_ID/session
owner seqid lanes         slot table/SEQUENCE
RENEW + reclaim           SEQUENCE renew/recovery
callback listener         backchannel callbacks
no pNFS                   pNFS/layout/DS sessions
    |                        |
    +---- RPC/TCP/AUTH_SYS --+
```

Suggested ownership:

- `nfs4/common`: protocol constants/types shared by RFC 7530 and RFC 8881; bounded XDR helpers; common attribute/ACL codecs; typed common operation arguments/results; COMPOUND envelope parameterized only at this low-level codec.
- `nfs40`: `Mount40`, SETCLIENTID lifecycle, owner schedulers/replay records, lease/reclaim state machine, v4.0 callback listener, and version-specific operation orchestration.
- `nfs41`: retain sessions, slots, backchannel, pNFS, layout and DS behavior; consume common codecs without moving policy into `nfs4/common`.
- `rpc`: retain transport and multiplexing, but expose a call primitive whose retransmission is selected by the protocol engine. Generic automatic retry must not decide replay safety for NFSv4.0 stateful operations.

## Consequences for implementation planning

1. First extract and test common wire codecs without behavior changes to v4.1. Include cross-version golden vectors from the RFC 7530 XDR and correct the false attribute-numbering comment.
2. Add a replay-policy-aware RPC call seam before building v4.0 state. This prevents owner-seqid correctness from being undermined by transport retries.
3. Implement `nfs40` establishment and a minimal stateless COMPOUND path, then owner/state lanes, lease/reclaim, and callbacks. The v4.0 engine should be testable against scripted reply loss before FAS2750 validation.
4. Port operation recipes by semantic family. Any helper that indexes `SEQUENCE` at result 0, reads session generation, touches layouts, or uses v4.1 OPEN WANT flags must be split before reuse.
5. Keep delegation disabled by default for migration workloads by registering no usable callback endpoint or immediately returning an unsolicited grant when possible; when explicitly enabled, use the dedicated v4.0 callback service and validate grant/recall/return/recovery on FAS2750.

## Risks discovered

- `attrs.rs` documents a nonexistent v4.0/v4.1 shift. Designing a duplicate v4.0 decoder around that claim would introduce incorrect bitmaps; the shared 0–55 attribute numbering should be verified with golden tests instead.
- The present generic RPC retry behavior is compatible with v4.1 slot replay but is not a safe implicit replay policy for v4.0 owner-sequenced mutations.
- Reusing `OpenArgs` unchanged would put v4.1-only delegation preference bits on a minor-version-0 OPEN.
- Reusing response indexes or `Mount41::compound` would silently require SEQUENCE, even when the individual operation codec is common.
- `StateManager`'s filehandle cache is useful as a high-level idea, but it does not model the protocol identity and serialization units needed by NFSv4.0.
